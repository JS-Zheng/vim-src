1. Introduction                                  *vim-src-introduction*

vim-src is a minimalist config loader for Vim and Neovim.

Supported editors:
- Vim 8.2 and newer
- Neovim 0.4.4 and newer

It loads configuration files relative to a base directory.

vim-src does NOT:
- manage plugins
- modify 'runtimepath'
- manage packages

==============================================================================

2. Philosophy                                    *vim-src-philosophy*

vim-src follows a simple design:

- minimal surface area
- deterministic behavior
- explicit over implicit
- no runtimepath magic

It is intended for early startup and bootstrap usage.

==============================================================================

3. Quick Start                                   *vim-src-quickstart*

Initialize:

    call src#init()

Load files:

    Src 'general.vim'
    Src 'mappings.vim'
    Src 'plugins'

4. Commands                                      *vim-src-commands*

                                                *:Src* *:Src!*
:Src[!] [{target} [, {opts}]]
        With no target, source the current buffer. Otherwise load a String path,
        directory, or List of String targets relative to the current base.

        [!] makes target availability optional. It does not suppress errors
        raised by readable scripts or base directory resolution failures, and
        has no effect on current-buffer errors.

        An empty target is rejected, or skipped with [!], so an unset
        variable such as `Src! $LOCAL_VIMRC` does not load the whole base
        directory. An empty List loads nothing.

        {opts} is an evaluated Dictionary with these optional keys:

        "optional"      Same availability policy as [!].
        "if"            Skip the entire call when false.

        Boolean options accept Number, Float, or Boolean values. Strings,
        Lists, Dictionaries, and Funcrefs are rejected.

        Arguments are evaluated in the script context of vim-src itself, so
        script-local variables (s:var) and variables of a Vim9 script or
        :def function are not visible, and a trailing "|" or comment is not
        supported. Use |src#()| in those cases: >

            call src#(s:local_file, 1)
<

5. Functions                                     *vim-src-functions*

                                                *src#init()*
src#init()
        Initialize vim-src. If an unrelated |:Src| command already exists, it
        is preserved and a warning is reported.

                                                *src#def_cmds()*
src#def_cmds()
        Define |:Src| explicitly, including when automatic command definition
        is disabled. This explicitly replaces an existing |:Src| command.

                                                *src#()*
src#([{path} [, {optional}]])
        Function version of |:Src|. With no arguments, source the current
        buffer. {path} may be a String or a List of targets. When {optional}
        is non-zero, missing or unreadable targets are ignored.

        {optional} must be a Number, Float, or Boolean value.

        A clean normal file buffer is sourced from disk. Modified, unnamed,
        and special buffers are sourced from their current memory contents
        through a temporary file, so |<sfile>| refers to that file there.

        Relative targets inside a file buffer resolve against the buffer's
        directory, except for |$MYVIMRC|, which keeps the same resolution
        context as at startup so it can be reloaded in place.

                                                *src#begin()*
src#begin([{path}])
        Push a new base directory scope. {path} must be a non-empty String;
        a relative {path} resolves against the current scope.

                                                *src#end()*
src#end()
        Pop one scope.

        Scopes that are still open when startup ends, for example because an
        error aborted the vimrc before its src#end(), are closed at |VimEnter|
        with a warning.

6. Configuration                                 *vim-src-config*

All options are under:

    let g:src = {}

                                                *g:src.base_dir*
g:src.base_dir
        Explicit base directory.

        Must be a String resolving to an absolute directory.
        "~" and "~/..." are accepted.

                                                *g:src.base_name*
g:src.base_name
        Name of the config directory.

        Must be a String.

        Default: "vimrcs"

        When empty, vim-src resolves a base directory directly.

                                                *g:src.def_commands*
g:src.def_commands
        Define |:Src| automatically from |src#init()|.

        Must be a Number, Float, or Boolean value.

        Default: 1

                                                *g:src.debug*
g:src.debug
        Enable debug messages.

        Must be a Number, Float, or Boolean value.

        Default: 0

Symlinks are always followed. The former g:src.follow_links option is no longer
supported.

7. Base Directory Resolution                     *vim-src-base-dir*

Resolution order:

1. Explicit override: |g:src.base_dir|

2. Named directory: |g:src.base_name| != ''

   Search:

        dirname($MYVIMRC)
        stdpath('config')          (Neovim)
        ~/vimfiles                 (Windows)
        ~/.vim
        $XDG_CONFIG_HOME/vim
        $VIM/vimfiles
        $VIMRUNTIME

3. Canonical config root: |g:src.base_name| == ''

   Search:

        stdpath('config')          (Neovim)
        ~/vimfiles                 (Windows)
        ~/.vim
        $XDG_CONFIG_HOME/vim
        dirname($MYVIMRC)
        $VIM/vimfiles
        $VIMRUNTIME

==============================================================================

8. Directory Loading                             *vim-src-dir*

When a directory is given:

    Src 'plugins'

vim-src loads all direct child *.vim files.

Example order:

    plugins/
        10-core.vim
        20-git.vim
        30-fzf.vim

    Src 'plugins'

Loads:

    1. 10-core.vim
    2. 20-git.vim
    3. 30-fzf.vim

Rules:

- non-recursive
- lexical order
- only *.vim
- hidden files ignored
- explicit symlinked files and directories are resolved and loaded
- symlinked *.vim children are loaded; directory children remain non-recursive

Note: on MS-Windows, |getftype()| reports a symbolic link to a directory as a
plain directory, so an explicit directory target that is such a link keeps its
link path as the loading context instead of the target path. Files inside it
resolve the same either way; only relative paths that leave it with ".." can
differ. Base directories from |src#begin()| and |g:src.base_dir| are always
resolved to their target path.

==============================================================================

9. Optional Files                                *vim-src-optional*

    Src! 'file.vim'

Missing files are ignored.

Unreadable direct children encountered during directory loading are also
ignored.

Errors inside files are still reported.

==============================================================================

10. Scope                                        *vim-src-scope*

Relative targets resolve against the innermost of:

1. the latest open |src#begin()| scope of the current file (or of the
   command line, when used interactively)
2. the directory of the file being loaded by vim-src
3. the default base directory (|vim-src-base-dir|)

So inside a loaded file, `Src 'x.vim'` loads a sibling of that file.

Example:

    call src#begin('plugins')
    Src 'git.vim'
    Src 'fzf.vim'
    call src#end()

    call src#begin('theme')
    Src 'colorscheme.vim'
    Src 'statusline.vim'
    call src#end()

==============================================================================

11. Errors                                       *vim-src-errors*

Errors follow this format:

    src: {category}: {message}

Categories:

    invalid argument
    invalid target
    resolution failure
    source failure

Unlike a plain |:source|, the first error inside a sourced file stops that
file, reports the file, original error, and throwpoint, and is rethrown as a
"source failure". Each enclosing sourced file reports its own context as the
error propagates.
